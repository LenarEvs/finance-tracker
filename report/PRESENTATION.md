## 1. Что это и зачем (20 сек)

> «Finance Tracker — full-stack приложение для учёта личных финансов.
> Поддерживает несколько валют, бюджеты по категориям, повторяющиеся транзакции

## 2. Стек и архитектура (20 сек)

> «Бэкенд — FastAPI + PostgreSQL + Alembic миграции.
> Фронтенд — React + TypeScript + Vite + Tailwind.
> Всё поднимается через Docker Compose: nginx, backend, frontend, postgres, scheduler.
> CI на GitHub Actions: lint, тесты, сборка.»

## 3. Демо — что показать и в каком порядке (80 сек)

### 3.1 Вход в приложение (10 сек)
- Открыть **http://localhost**
- Войти с тестовым аккаунтом (`alice@example.com` / `secret`)
- Подчеркнуть: два изолированных пользователя

### 3.2 Дашборд (15 сек)
- Показать **круговую диаграмму** расходов по категориям
- Показать **линейный график** доходы vs расходы за 6 месяцев
- Показать **топ-5 категорий** и сводку (доходы / расходы / баланс)

### 3.3 Транзакции (15 сек)
- Показать список с фильтрами (дата, тип, категория)
- Добавить новую транзакцию через форму
- Подчеркнуть: **мультивалютность** — поле валюты и курс на момент операции

### 3.4 Категории (10 сек)
- Показать сетку категорий с иконками и цветами
- Создать новую категорию (иконка-пикер, color picker)
- Подчеркнуть: мягкое удаление — архивирование, история не теряется

### 3.5 Бюджеты (10 сек)
- Показать прогресс-бары по категориям за текущий месяц
- Указать на цветовую индикацию: зелёный / оранжевый / красный

### 3.6 Журнал изменений (10 сек)
- Открыть Audit Log
- Показать записи с пользователем, временем и значениями до/после
- Подчеркнуть: фиксирует все CREATE / UPDATE / DELETE

### 3.7 Swagger UI (10 сек)
- Открыть **http://localhost/docs**
- Показать документированный API (39 эндпоинтов)

## 4. Ключевые технические решения (30 сек)

> **JWT с ротацией refresh-токенов** — refresh-токен хранится в БД по jti,
> при каждом обновлении старый удаляется. Перехваченный токен не может быть использован дважды.

> **`amount_base` как GENERATED COLUMN** — PostgreSQL сам пересчитывает сумму в базовой валюте
> при изменении курса. Нет риска рассинхронизации между Python-кодом и БД.

> **Audit log в сервисном слое, не через триггеры** — только так есть доступ к `user_id` из JWT-контекста.

> **Scheduler как отдельный Docker-сервис** — изолирован от API, перезапускается независимо,
> не блокирует HTTP-запросы при создании повторяющихся транзакций.
